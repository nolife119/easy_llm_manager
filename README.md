# Easy LLM Manager 0.5

Windows에서 GGUF 모델과 llama.cpp 서버를 로컬 브라우저로 관리하는 경량 도구입니다. Python 3.10+ (3.12 권장), 기본 라이브러리 UI. 외부 추론 서비스 없이 동작합니다. 모델 다운로드에만 huggingface_hub 및 승인된 네트워크가 필요합니다.

## 3단계 시작

1. ZIP을 새 폴더에 풀고 `start.bat`을 실행합니다. 화면은 localhost (기본 127.0.0.1:8765)에서 열립니다.
2. 기존 정상 실행 기록이 있다면 **실행 · 모니터 → 마지막 정상 설정 복원**을 누릅니다. 없다면 **엔진 · 환경**에서 기존 llama-server.exe 및 모델 폴더를 지정하고 실행 모델을 선택합니다.
3. **서버 시작**으로 현재 설정을 그대로 실행합니다. 메모리 경고는 실제 구동 결과와 다를 수 있습니다.

이전 버전과 같은 %LOCALAPPDATA%/InklingManager 폴더를 사용합니다. 모델 파일, 소스, 런타임, API 키를 옮기거나 다시 다운로드하지 않습니다. 기존 매니저와 추론 서버는 먼저 종료하세요. ZIP 전체를 풀어야 합니다 (manager.py, speed.py, ui.html, config.json, start.bat).

## 속도 최적화: 목표 50 tokens/s

기준 사례: H100 NVL 94GB 2장, Inkling 2 Small UD-IQ1_M, 512K, FP16 KV, GPU 전체 상주, Vision OFF, no mmap, 단일 슬롯, Logical 2048 / Physical 256, Medium reasoning. 실제 사용 가능한 VRAM은 nvidia-smi와 엔진에 따라 다릅니다.

1. 서버를 정상적으로 실행해 기본 동작을 확인하고 중지합니다. 다운로드/빌드 등의 작업도 중지합니다.
2. **속도 최적화 → 마지막 정상 설정 사용**. 정상 기록이 없는 경우에만 512K 프리셋을 불러오고 엔진/모델 경로를 확인합니다.
3. 호환성 검사를 선택합니다. 기존 엔진의 --help를 읽어 N-gram Mod/Simple, GPU 샘플링, DSpark, Row/Tensor 옵션의 존재를 감지합니다. 옵션 존재는 모델 지원 보장이 아닙니다.
4. 목표 50 t/s 및 4K 입력으로 가속 자동 시험을 시작합니다. 정상 구동을 확인한 동일 조건에서만 메모리 추정 경고 허용을 선택합니다. 실험 체크박스는 초기 시험에서는 끄는 것을 권장합니다.
5. 결과에서 코드 편집형 / 일반 설명형의 속도, 기준 greedy 출력 일치 여부 및 목표 통과를 확인합니다. 두 유형 모두 목표를 충족한 후보를 우선하고, 그렇지 않으면 출력 일치 후보 중 조화 평균 속도가 가장 높은 설정을 추천합니다. **가장 빠른 검증 설정 적용 · 저장 → 서버 시작**. 실패하더라도 이전 Health-OK 기록은 보존됩니다.

자동 시험은 같은 모델 파일, 할당 컨텍스트, KV 정밀도/위치, batch/ubatch, 엔진 및 GPU 구성을 고정합니다. 기준 및 가속 후보마다 임시 localhost 서버를 순차적으로 실행하고, 코딩과 일반 합성 입력(출력 128 tokens, greedy, cache_prompt=false) 두 건을 측정합니다. 자체 테스트의 출력 일치 여부는 간단한 회귀 검사이지 모든 실제 출력의 품질 또는 수치적 동일성에 대한 인증이 아닙니다. 4K/8K/32K 입력 검증은 할당된 512K를 모두 채우는 테스트가 아닙니다. 모델 로딩 제한은 후보당 30분, 각 생성 요청 제한은 5분입니다. 실제 성능은 장문 길이, 프롬프트, 샘플링, 추측 토큰 채택률 등에 따라 달라집니다. 50 t/s 달성은 미검증 목표이며 보장하지 않습니다.

### 실험 옵션

- N-gram Mod / Simple: 별도 모델 다운로드 불필요. 반복되는 코드에서 추측 디코딩의 효과가 클 수 있으나 일반 입력에서는 느려질 수도 있습니다.
- GPU 샘플링: 현재 --help에서 지원을 확인한 경우만 활성화합니다.
- PCIe P2P: 옵션을 켜면 실행 프로세스에 GGML_CUDA_P2P=1을 설정합니다. GPU/BIOS/드라이버와 호환되지 않으면 오류 또는 결과 차이가 날 수 있습니다.
- Row/Tensor split: 기본 Layer와 비교합니다. 모델 아키텍처 지원, 추가 VRAM 및 GPU 간 통신에 따라 실패할 수 있습니다. Tensor와 GPU 샘플링 동시 활성화를 제한합니다.
- CUDA Graph: 엔진 기본과 비활성화를 비교합니다. 비활성화는 가속을 보장하지 않습니다.
- DSpark: 명시적으로 호환 GGUF를 지정하고, 엔진에 draft-dspark 옵션이 있는 경우만 시험합니다. 별도 가중치와 버퍼 크기는 현재 메모리 추정에 포함되지 않으므로 초기화에 실패할 수 있습니다. 자동 다운로드나 변환은 지원하지 않습니다.

참고: [llama.cpp speculative decoding](https://github.com/ggml-org/llama.cpp/blob/master/docs/speculative.md), [multi-GPU guide](https://github.com/ggml-org/llama.cpp/blob/master/docs/multi-gpu.md), [server options](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md). 실제 설치된 엔진의 옵션과 결과가 우선합니다.

## 메뉴

- **실행 · 모니터**: 모델, 컨텍스트, 생각 깊이, Vision, 시작/중지/재시작, 설정 저장, GPU/RAM, Prefill/Decode, 오류 및 로그. 세부 실행 설정은 모델 파일, 메모리 및 처리량별로 접어서 표시합니다. 자동 메모리 맞춤은 별도로 제공하며 사용자가 적용하기 전에는 변경하지 않습니다.
- **속도 최적화**: 호환성 검사, 고정 조건 성능 비교, 시험 결과 및 가속 수동 설정.
- **모델 관리**: 로컬 GGUF shard 검사, 모델 선택, 파일 크기 조회 및 다운로드. 실행 모델 선택과 다운로드 대상은 분리합니다. 기존 파일은 재사용합니다.
- **엔진 · 환경**: 기존 엔진과 CUDA 환경 검사, 공식 CUDA 바이너리 별도 설치, 현재 Git 체크아웃 그대로 빌드 / 지정 ref 빌드, 로컬 진단.
- **접속 · 인증**: 접속 범위와 포트, 서버 IPv4, 키 발급/폐기, 로컬 인증 시험. 사내망 접속은 승인된 범위에서 별도 방화벽 설정이 필요하며 API 키 필수입니다. 관리 API는 localhost에만 노출합니다. 키 파일은 OS 로컬 접근 권한으로 보호하며 암호화되어 있지 않습니다.

## 문제 해결

- Windows 시스템 RAM이 지나치게 높음: 모델 로딩 방식을 직접 읽기(no mmap)로 비교하세요. mmap 상주 페이지와 실제 private commit은 다릅니다.
- KV cache 양자화 관련 오류: FP16으로 되돌리세요. GPU 최대 모드는 체크포인트를 줄입니다. 장문 수정 시 캐시 재처리 비용이 증가할 수 있습니다.
- 엔진과 GGUF 로딩 오류: 기존 정상 파일을 보존하고 호환성 검사 및 해당 엔진 --help를 확인하세요. 새 엔진으로 덮어쓰지 않습니다.
- 속도가 낮음: 다운로드 완료 후 동일 입력을 비교하세요. Prefill과 Decode는 별도 지표입니다. Medium reasoning은 출력 토큰 수를 줄일 수 있지만 t/s 자체를 보장하지 않습니다.
- 포트 접근 실패: 서버가 Health OK인지, 사내망 모드 및 키인지 확인하세요. 방화벽 설정은 관리자 승인 필요. 접속 주소/API 키를 외부에 공유하지 마세요.
